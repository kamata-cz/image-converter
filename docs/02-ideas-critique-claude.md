## 0. 採点表そのものの偏り（前置き）

## 3. 上位 3 案（元の I1・I2・I3）の致命的な弱点

**I1 提出写真ぴったり**
- 【推測】マイナンバーで実際に引っかかるのは容量より「HEIC 不可」。スマホの写真は数 MB で、20KB〜7MB に普通は収まる。中身は I5（HEIC→JPEG、gap 2）に近づく。iOS Safari が HEIC を JPEG にして渡すなら（要約の不明点）、悩みはさらに小さい。**作り始める前に iPhone 実機で確かめること**。
- 【事実】保有枚数率は 2026 年 1 月末で 81.2%。【事実】スマホ申請は申請の流れの中でカメラ撮影して添付する。新規の需要は細っている。【推測】10 年ごとの更新の波はありうるが、件数は未確認。
- 規約・誤解: 「通る」「OK」とは書かず、「形式・容量・寸法だけを確認、顔・背景・影は対象外」と結果の横に毎回書く。公式に見える名前や配色は避ける。プリセットの値ごとに出典 URL と確認日を表示する（パスポートの 600KB のように値は変わる）。
- 収益と 20 時間: 広告には独自ドメインへの移転と AdSense の審査が要る（パス付き URL は不可、ツールだけでは「内容が乏しい」扱いの恐れ。要約 §4）。【推測】HEIC の組み込み 3〜5 時間、不具合直し 3〜4 時間、Primer の見た目 3〜5 時間を引くと、解説ページを何本も書く余裕は無い。期限内に収益が出る見込みは低い。

**I2 出品画像そろえ**
- 正方形・余白・一括・ZIP は無料の海外ツールに揃っている（§2）。【推測】BASE・Shopify は表示用の画像を自動で作るので、「条件に合わない」より「見た目をそろえたい」需要。日本の販売先ごとの必須条件が公式に見つからないと、プリセットの根拠が作れない。
- 買い切りのライセンスキーはブラウザだけでは守れない（要約 §4）。20 時間には収まるが、払う理由が弱い。

**I3 ブログ画像まとめ軽量化**
- 【推測】WordPress・はてな・note の利用者は、プラグインや自動変換で足りる。本当に困るのは「ページ別フォルダに 100 枚超を整理した、静的サイトや受託の制作者」（要約が引いた Reddit の投稿もこの像）。名前を「ブログ」から「サイト制作」寄りに変えるべき。
- 【事実】フォルダ読み込みは全ブラウザで可（§1）。【推測】大量処理は iOS の canvas 上限・メモリで落ちるので、PC 向けと割り切れば 20 時間に収まる。課金は Cloudflare Pages＋決済リンクへの移転が前提で、期限内は寄付まで。

## 4. 組み合わせ案

1. **I3＋I9「フォルダごと軽量化＋結果一覧」**（推奨）: フォルダを入れる → 幅・形式・品質を一括指定 → 構成を保った ZIP → 前後の容量・寸法の一覧、失敗分だけやり直し。I9 単独の弱さ（LIBRA Works に report.csv あり）を I3 の構成保持で補う。TinyPNG がフォルダ処理を最上位プランだけに置いている（§2）ので、将来の有料枠の候補が明確。
2. **I1＋I6＋I5「提出用に整える」を 1 つの処理と複数の入口ページで**: 処理は「HEIC 読み込み → 上下限つき目標容量 → 寸法 → 技術条件の一覧」の 1 本。入口を「マイナンバー用」「100KB 以下」「HEIC を JPEG に」など用途別の URL に分ける。【事実】Codia が KB ごとに別ページを持つのも同じ形。広告で回すならこちら、課金するなら 1。

## 5. 10 案に無い案（1 件）

**N1 書類の写真を提出用 PDF にまとめる（送信しない）**
- 内容: スマホで撮った書類画像を並べ替え、グレースケール化・解像度の指定・合計容量の上限を指定して 1 つの PDF にする。
- 根拠: 【事実】e-Tax のイメージデータは PDF で、1 回の送信に容量とファイル数の上限がある（国税庁東京局のページ。文字化けがあり、8.0MB と 14.0MB の両方の記載が読めたので値は要再確認）。【事実】Smallpdf・Adobe の画像→PDF は、どちらもアップロードして処理する（ページの説明）。源泉徴収票や身分証のように外に出したくない書類ほど「送信しない」が効き、画像より使う理由が強い。
- 弱点: 【推測】iPhone の書類スキャンなど OS 標準で足りる人が多い。PDF 部品のライセンスと容量の当て方は未調査。既存の画像処理の資産は半分ほどしか使えない。

## 6. 結論（私の上位 3 案）

1. **I3＋I9**（サイト制作者向けのフォルダ一括）: 払う機能として売られている証拠があり（TinyPNG Ultra）、ブラウザで構成を保つ ZIP は見つからず、全ブラウザで作れる。
2. **I1＋I6＋I5**（提出用に整える、用途別の入口）: 検索で来る需要は明確だが単独の差は薄いので、広告用の入口群として作り、「技術条件だけ」と明示する。HEIC の実機確認が前提。
3. **I2**（販売先プリセット）: 業務で繰り返し使う点だけが強み。日本の販売先の必須条件の公式資料が見つかれば残し、見つからなければ N1 と入れ替える。
