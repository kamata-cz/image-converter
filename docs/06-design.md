## 4. 画面の状態と、押せるボタン

| 状態 | 押せる | 押せない（その場に出す理由） |
|---|---|---|
| ① 入れる前 | フォルダを選ぶ・画像を選ぶ・ドロップ・設定 | 軽量化を始める（画像を入れると始められます）、ZIP（画像を入れると保存できます）、やり直し、CSV、絞り込み |
| ② 読み込み済み | 軽量化を始める（緑）・入れ直し・設定 | ZIP（処理を始めると保存できます）、CSV、やり直し、絞り込み |
| ③ 処理中 | 中止する（同じ位置のボタンが切り替わる） | 入れ直し・設定（処理中は変えない）、ZIP（処理が終わると保存できます）、CSV |
| ④ 完了 | ZIP（緑）・CSV・要確認だけやり直す（要確認があるとき）・絞り込み・同じ設定でもう一度 | やり直し（要確認が 0 件なら「要確認はありません」） |
| ④' 中止した | 続きから始める・終わった分の ZIP・CSV | — |
| ⑤ Safari | ② と同じ。形式の WebP だけ選べない | WebP（Safari では WebP を作れないため、JPEG か PNG を選んでください） |

- 入力の誤り（長い辺 320〜8000px、目標 20〜20000KB の範囲外・数字以外）は、枠を危険色にして説明の行に直し方を出す
- 読み上げ: 進み具合は role=progressbar と aria-live（32 枚ごと・開始・完了・中止）、トーストは role=status

## 5. 段階 7 実装への引き継ぎ
- 今の src は Tailwind v4。Primer の値に寄せる方法は 2 つ:
  - A Tailwind をやめ、`primer-base.css`＋見本の `app.css` をそのままアプリの CSS にする（推奨）。見本と実装が同じファイルになり、値を二重に持たない。Tailwind のクラスは書き換えが要るが、画面は 1 つで作り直す予定なので手間は増えない
  - B Tailwind を残し、`@theme` に Primer の値を入れる。既存のクラスを活かせるが、見本（CSS 変数）と実装（Tailwind のテーマ）で値を 2 か所に持つことになる
- 見本の `app.js` は見た目の確認用（ダミーのデータ）。実装は spike/ の測定済みの処理（Worker 4 並列・目標容量の探索 7 回・fflate の Zip ストリーム・拡張子での判定）を React に移す
- 外部リンク（GoatCounter・OFUSE・第三者ライセンスの表示）は「※未設定」。登録後に差し替える
