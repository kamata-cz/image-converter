# 要件定義書: フォルダまるごと軽量化（仮称）（2026-11-04 版、承認: 済 2026-11-04）

根拠の記号: S=`01-research/summary.md` の節、C=`01-research/raw/C-tech-claude.md`、F=`01-research/raw/F-existing-claude.md`、決定は `decisions.md`。

## 1. 一言で
写真の多いブログ運営者が、記事用の画像をフォルダごと入れるだけで、同じフォルダ構成のまま軽くして ZIP で受け取れる。画像はどこにも送らない。

## 2. 利用者と場面
| 利用者像 | 場面 | 今の困りごと（根拠） |
|---|---|---|
| 写真の多いブログ運営者（WordPress など） | 旅行・料理などの記事を書く前に、月ごと・記事ごとのフォルダの写真をまとめて軽くする | 無料ツールは 20 枚ずつで、上げて・保存して・解凍してを繰り返す。100 枚超のために有料版へ移った人もいる（S3） |

## 3. MVP（最初の公開に入れる機能）
すべて無料。PC のブラウザ（Chrome・Edge・Safari・Firefox）で全機能、スマホは表示が崩れず数枚なら使える程度。ただし Safari では WebP を選べない（JPEG・PNG のみ。理由を画面に出す。WebAssembly の WebP 部品で補うかは 5・6 で判断）。1 回に扱うのは 500 枚まで（04 ③）。
（2026-11-04 改訂: 4 実現性の検証の修正提案 8 件を反映。根拠は `04-feasibility.md`）

| 機能 | 内容 | 受け入れ条件（何ができたら完成か） |
|---|---|---|
| M1 入れる | フォルダを選ぶ・ドロップする。数枚のファイルでもよい（1 つの画面にまとめる） | フォルダの中の画像を、下の階層まで相対パスつきで読み込める。画像かどうかは拡張子で判定し、画像以外は「対象外 n 件」と出す。名前が `.` で始まる隠しファイルは対象外の件数にも数えない。ドロップで読めないブラウザでは「フォルダを選ぶ」へ案内する |
| M2 設定 | 長い辺の最大、形式（WebP・JPEG・PNG）、1 枚あたりの目標容量 | AVIF は選択肢に出さない。設定はブラウザに保存され、次回も同じ |
| M3 目標容量への自動調整 | 指定した容量以下になるように画質を自動で探す | 届かないものは「目標を超過（最小 nKB）」として要確認にする。探す回数は 1 枚 7 回まで。目標の 90〜100% に入ったら止める |
| M4 処理と進み具合 | まとめて処理し、進み具合を出す | 処理は Worker で行う。進み具合（n / 全体）が止まらずに増え、途中で止められる。画面の止まりは 1 回 200ms 未満（目安） |
| M5 結果の一覧 | ファイルごとに 前→後の容量、寸法、状態（完了・目標超過・読めない形式）と理由 | 合計の容量（前→後）と要確認の件数が一目で分かる。「要確認だけ表示」で絞れる |
| M6 要確認だけやり直す | 設定を変えて、要確認のものだけ処理し直す | 完了したものは処理し直さない |
| M7 ZIP で保存 | 元と同じフォルダ構成・名前（拡張子だけ変わる）で 1 つの ZIP | 解凍すると元の構成と同じ。同じ名前がぶつかるときは連番を付ける。ZIP の中の名前は Unicode の NFC 形式にそろえる。1 つの ZIP が 500MB を超えたら分ける（ストリーム方式で作る） |
| M8 CSV で書き出す | 結果の一覧を CSV で保存 | Excel で開いて文字化けしない（UTF-8 BOM つき） |
| M9 既存の不具合直し | F・C で見つかったもの | 縦写真が正しい向き（手動の回転をやめてブラウザに任せる。EXIF のある JPEG で変換が止まる不具合も解消）、透過を JPEG にすると白背景、読めないファイル（HEIC を含む）は「読めない形式」と表示して止まらない。読めた場合（Safari の HEIC など）はそのまま処理する。画面は日本語、lint が通る |
| M10 信頼の表示 | 「画像は送信しません」と、撮影情報（位置情報など）は保存時に消えることを画面に書く | 表示の内容が実際の動きと一致する |
| M11 寄付と簡易計測 | 寄付のリンクと、Cookie を使わない表示回数の計測 | 計測を使うことを画面に明記。サービスは 5 で決める |

## 4. やらないこと（MVP では作らない、理由つき）
- Safari 以外での HEIC（iPhone 写真）の読み込み: WebAssembly の部品（約 1.5MB、LGPL か更新の止まった MIT）が要る（C）。Safari は標準で読めるので、読めたものは処理する（M9）
- AVIF での書き出し: 標準ではどのブラウザも書き出せず、WebAssembly（約 3.5MB）が要る（C）
- 元のフォルダへの直接上書き: Chrome・Edge だけの機能で、元画像を壊す危険もある
- アカウント・クラウド保存: 画像を送らない方針と合わない
- 有料機能: 初版は全部無料で反応を見る。GitHub Pages は商取引に使えない（S4）
- 切り抜き・透かし・SNS 用の見切れ確認: 今回の案の範囲外

## 5. 画面の一覧（見た目は 6 で決める。土台は `docs/mock/project/Main.dc.html`）
1 画面: ①入れる（フォルダ・ファイル）②設定（右の列）③結果の一覧（合計・要確認・一覧・ZIP・CSV・やり直し）

## 6. 技術と規約の前提（4 実現性の検証で確かめる）
| 前提 | 根拠 | 検証方法 |
|---|---|---|
| フォルダ選択（`webkitdirectory`）が 4 つのブラウザで使える | MDN で Baseline 2025（批評で照合済み） | Chrome・Safari・Firefox で 3 階層のフォルダを読み、相対パスを確認 |
| フォルダのドロップで中身を読める | 未確認 | 同上。読めないブラウザでは「フォルダを選ぶ」ボタンに案内する |
| 目標容量の自動調整が実用的な速さ | 未確認 | 20 枚の写真で、1 枚あたりの時間と探索回数を測る |
| 200 枚でもメモリと画面が持つ | iOS は canvas 4096×4096 まで（MDN）。PC は未確認 | Worker と OffscreenCanvas の有無で 200 枚を処理し、時間とメモリを見る |
| ZIP を作れる大きさ | fflate（MIT、約 8kB） | 合計 500MB で ZIP を作り、保存できるか |
| EXIF の二重回転を直せる | 既存の EXIF 読み取りは例外で止まり（変換が終わらない）、読み取りを直しても回転を重ねると二重回転になる（3 エンジンで実測、04 ②6） | 向き 6・8 の写真で確認 |

4 の結果（2026-11-04）: 上の 6 件はすべて「できる」または「条件付き」。詳細と、本物の Safari・Firefox で手で確かめる 9 件は `04-feasibility.md`。

## 7. データとプライバシー
- 端末の外に出すデータ: 画像は無し。簡易計測を入れる場合はページの表示回数だけ（Cookie なし、個人を特定しない）
- 権限: 特別な権限は無し（ファイル・フォルダの選択は利用者が毎回行う）
- 撮影情報（位置情報など）は保存時に消える。消したくない人への対応は MVP では行わない

## 8. お金（5 で詳しく決める）
