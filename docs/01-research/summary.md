## 1. 結論

1. **「ブラウザ内で変換・圧縮・一括・HEIC・EXIF 削除」はもう差別化にならない。** 日本語の無料ツールが同じ機能を揃えている（はちのす: 100 枚・HEIC・EXIF 自動削除・SNS プリセット、LIBRA Works: 200 枚・HEIC・report.csv・オフライン可、ToolBox: 用途別プリセット・ZIP）。
2. **機会は「変換」ではなく「目的を満たすまで仕上げる」こと。** codex と Claude で一致: 提出条件（形式・容量の上下限・寸法）に合わせて適否を表示する／フォルダ構成や名前を保った一括処理／処理後の確認と失敗理由の表示。
3. **お金を払う理由として確認できたのは「大量処理の手間を省く」だけ。** 広告除去・透かし除去だけを理由に払った体験談は見つからなかった。日本語の変換サイトは、自社の別事業への集客か広告で成り立っており、変換そのものを売る例は見つからなかった。
4. **GitHub Pages では収益化できない前提で考える。** 公式に「オンラインビジネス・EC・商取引や商用 SaaS を主目的とするサイト」は不可（寄付は可）。広告や課金をするなら、Cloudflare Pages など商用可の公開先と独自ドメインへ移す必要がある（費用は 5 で計算）。
5. **公開中のサイトは今、見た目が崩れている**（Tailwind v4 なのに v3 の書き方。1 行で直る見込み）。ほかにも、AVIF が黙って WebP になる、縦写真が横倒しになる（EXIF の二重回転）、透過が黒になる、HEIC で止まる、UI が英語のみ、という不具合がある。
6. **20 時間で収まるのは「1 つの利用場面に絞った仕上げ機能」と既存の不具合直し。** 形式の追加（AVIF・HEIC は WebAssembly で 1.5〜3.5MB 増える）や API・CDN 化に広げる余裕はない。

## 2. 競合の地図と手薄な点

| 型 | 例 | 強み | 弱み・手薄な点 |
|---|---|---|---|

## 3. 利用者の悩み（根拠つき）

| 悩み | 根拠 | 補足 |
|---|---|---|
| 一括の枚数制限と、繰り返しの操作 | TinyPNG の 20 枚ずつに困る note（2026-06）、100 枚超のために有料版へ移ったブログ、40 枚を 1 枚ずつ保存した学校の例、Squoosh FAQ「一番多い要望」 | 有料化の根拠が一番具体的 |
| HEIC が使いたい先で使えない | マイナンバーカード申請は HEIC 不可（公式）、PowerPoint で選べなかった体験、同僚の相談 | 「開く」と「提出先で使える」は別の課題 |
| WebP で保存すると編集・貼り付けで止まる | 楽天画像を扱う EC 担当、素材配布者の Q&A、拡張子だけ書き換える投稿 | WebP「へ」と WebP「から」の両方に需要 |
| 画像をサイトに上げる不安 | 身分証の写真をリサイズした人の相談（WEB110）、児童の写真を外部に送れない学校 | 使うかどうかの条件にはなるが、払う理由かは不明 |
| 狙った容量に合わせにくい | Squoosh Issue #1422（目標容量の入力を要望。照合済み） | 申請は 20KB〜7MB など上下限がある |
| SNS で見切れる | Instagram の 4:5 で上下が切れる体験 2 件 | リサイズだけでは解決しない |

公式の提出条件の例: マイナンバーカード（JPEG、20KB〜7MB、480〜6000px、HEIC 不可）、BASE（推奨 1280×1280px、10MB 以下、JPG・PNG・GIF）。一方、Shopify と note は自動で変換・最適化するので、事前の変換は要らない。

想定利用者の仮説（B）: 写真の多いブログ運営者／iPhone の写真を Windows の資料に使う人（学校・職場、ソフトを入れられない）／複数の販売先に画像を用意する小規模 EC 担当／申請・提出写真を一度だけ整えたい人。

## 4. 技術と規約で「できない／条件付き」のこと

| 項目 | 判定 | 要点 |
|---|---|---|
| WebP の書き出し | 条件付き | Safari（Mac・iOS）は canvas から書き出せない |
| AVIF の書き出し | canvas ではできない | Chrome 156 で試すと PNG になった。jSquash（Apache-2.0、約 3.5MB）なら可能 |
| HEIC の読み込み | 条件付き | Safari 17 以降だけ。他は libheif 系（LGPL）か heic2any（MIT、2024 年から更新なし） |
| 大きな画像・大量処理 | 条件付き | iOS の canvas は 4,096×4,096px まで（MDN）。Worker と OffscreenCanvas は主要ブラウザで可 |
| フォルダごとの処理 | 条件付き | File System Access API は Chrome・Edge だけ |
| canvas で失われるもの | 仕様 | EXIF・位置情報は消える（削除機能は実質タダ）。透過を JPEG にすると黒。アニメーションは 1 コマ目だけ |
| PWA | 条件付き | インストール・オフラインは可。他アプリから画像を受け取る機能は Chrome（Android・PC）だけ |
| Chrome 拡張 | できる | MV3 で右クリックから変換保存。登録費 $5（2020 年の公式ブログの値、現行額は不明） |
| GitHub Pages で収益化 | 不可寄り | 商取引・商用 SaaS は不可、寄付は可、広告は記載なし。Vercel の無料プランは非商用のみ（照合済み） |
| AdSense | 条件付き | `/image-converter/` のようなパス付きの URL は登録不可。ツールだけのページは「内容が乏しい」と判断されうる |
| 課金 | 条件付き | Stripe Payment Links 3.6%、Lemon Squeezy 5%+50¢、Gumroad 10%+50¢。ブラウザだけでは有料機能を守れない（解除されうる） |

形の比較（C の推奨）: Web を主にして軽い PWA を足す。収益化するなら Cloudflare Pages と独自ドメインへ移す。

## 6. 食い違った点と裁定

| 食い違い | 裁定 |

## 7. 案出しに使う論点

1. 入口を「形式」ではなく「目的」にする: 申請・提出に通す／資料に貼れるようにする／ブログを軽くする／販売先の条件に合わせる
2. 条件の適否を表示する: 形式・容量の上下限・寸法を指定し、満たしたかを一覧で見せる（目標容量に合わせた自動調整も含む）
3. 一括処理の体験: フォルダ構成と名前を保つ（Chrome・Edge）、ZIP、失敗した分だけやり直す
4. 「送信しない」を信頼の土台にする（課金理由ではなく、使ってもらう条件）。位置情報は消し、撮影日時は残す、などを選べるようにする
5. WebP「から」JPG/PNG に戻す需要（拡張・右クリックの場面）
6. 収益化の形の候補: 大量処理の上限を外す買い切りまたはサブスク／用途別の解説ページと広告（独自ドメインが前提）／寄付（GitHub Pages のままで可）
7. 既存の不具合直し（スタイル崩れ・AVIF・EXIF の二重回転・透過・HEIC・日本語化）は、どの案を選んでも先に要る
8. 20 時間の制約: 1 つの場面に絞る。AVIF・HEIC を加えるかは、場面の必要次第で決める
